## สิ่งที่ต้องมี

- Node.js เวอร์ชัน LTS (20 ขึ้นไป)
- MongoDB Community Server ที่กำลังทำงานอยู่ (พอร์ตเริ่มต้น 27017) — หรือใช้ MongoDB Atlas แล้วใส่ connection string ใน `.env`
- Google Chrome เวอร์ชันล่าสุด (แนะนำ)

## วิธีติดตั้งและรัน

```bash
cd server
npm install
cp .env.example .env        # Windows: copy .env.example .env
npm run seed                # สร้างข้อมูลตัวอย่าง
npm start                   # เปิด http://localhost:3000
```

ระหว่างพัฒนาใช้ `npm run dev` (รีสตาร์ตอัตโนมัติด้วย nodemon) — ทุกคำสั่ง `npm` รันในโฟลเดอร์ `server/`

### ตั้งค่า `.env`

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `PORT` | พอร์ตเว็บ | `3000` |
| `MONGO_URL` | ที่อยู่ MongoDB | `mongodb://127.0.0.1:27017/univibe` |
| `SESSION_SECRET` | ข้อความลับสำหรับเซ็น session (ควรเปลี่ยน) | ค่าสำหรับพัฒนา |

### คำสั่ง seed

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run seed` | สร้างข้อมูลตัวอย่าง (ข้ามถ้ามีอยู่แล้ว) |
| `npm run seed:reset` | ล้างข้อมูลทั้งหมดแล้วสร้างใหม่ |
| `npm run seed:clear` | ล้างข้อมูลทั้งหมด |
| `npm run seed:check` | ตรวจไฟล์ข้อมูลตัวอย่าง (ไม่ต้องใช้ MongoDB) |

### ลองสาธิตตามลำดับ

1. สมัครนักศึกษาด้วยรหัส `660911085` วันเกิด `2004-05-14` → เข้าหน้าหลักทันที และเข้ากลุ่มวิชา CS101 อัตโนมัติ
2. ลองสมัครด้วยวันเกิดผิด → สมัครไม่ได้
3. สมัครเป็นอาจารย์ → รออนุมัติ → เข้าสู่ระบบเป็น `admin` อนุมัติที่เมนู "จัดการระบบ"
4. เข้าสู่ระบบเป็น `somchai` เขียนโพสต์พร้อมรูปและแฮชแท็ก
5. เข้าสู่ระบบอีกบัญชี (เปิดหน้าต่างไม่ระบุตัวตน) ค้นหา "สมชาย" → ติดตาม → ถูกใจและแสดงความคิดเห็น
6. กลับมาที่ `somchai` จะเห็นเลขแจ้งเตือนที่กระดิ่ง กดแล้วไปที่โพสต์
7. ลองโพสต์แบบ "เฉพาะผู้ติดตาม" แล้วดูจากบัญชีที่ไม่ได้ติดตามจะไม่เห็นโพสต์นั้น
8. เปิดหน้าโปรไฟล์ของอีกคน → "ส่งข้อความ" แล้วคุยกัน 2 หน้าต่าง ข้อความขึ้นทันที เห็น "กำลังพิมพ์..." และ "อ่านแล้ว"
9. สร้างกลุ่มปิดที่ `/groups.html` อีกบัญชีค้นหาแล้วขอเข้าร่วม → เจ้าของกลุ่มอนุมัติ → แชทกลุ่มด้วยกัน
10. บล็อกกันที่หน้าโปรไฟล์ → ส่งข้อความและติดตามกันไม่ได้ (เลิกบล็อกได้ที่หน้าโปรไฟล์หรือหน้าตั้งค่า)
11. เข้าสู่ระบบเป็น `admin` → "จัดการวิชา" ลองเพิ่มวิชาในห้อง 301 วันจันทร์ 09:00 → ถูกบล็อกเพราะห้องชนกับ CS101 แล้วเปลี่ยนห้องให้บันทึกได้ และลงทะเบียน `660911001`
12. เข้าสู่ระบบเป็น `teacher1` → วิชา CS101 → โพสต์ประกาศและสร้างงาน → ลองแก้เวลาเรียนให้ชนกับวิชาที่นักศึกษาเรียนอยู่ จะมีกล่องเตือนให้ยืนยัน
13. เข้าสู่ระบบเป็น `somchai` ส่งไฟล์ PDF (ลองส่งไฟล์ปลอมนามสกุล .pdf จะถูกปฏิเสธ) → `teacher1` ให้คะแนน → `somchai` เห็นคะแนนและแจ้งเตือน ถ้าส่งใหม่คะแนนเดิมจะถูกล้าง
14. สมัคร `660911085` แล้วเปิด EN201 กด "ขอเข้าร่วมเป็นกรณีพิเศษ" → `teacher1` อนุมัติที่แท็บ "คำขอเข้าร่วม"
15. เข้าสู่ระบบเป็นผู้ใช้อื่นแล้วกด "รายงาน" ที่โพสต์ของ `somchai` เลือกเหตุผล → เข้า `admin` ที่ "จัดการระบบ" แท็บ "รายงานโพสต์" เลือก "ลบโพสต์" หรือ "ไม่พบการละเมิด" → ผู้รายงานได้แจ้งเตือนผล
16. แท็บ "ผู้ใช้" ค้นหาผู้ใช้แล้วกด "ระงับ" → ผู้ใช้ถูกออกจากระบบทันที (แชทเรียลไทม์ถูกตัดด้วย) เข้าสู่ระบบไม่ได้ จนกว่าจะกด "ปลดระงับ"
17. แท็บ "โพสต์/ความคิดเห็น" ค้นข้อความแล้วกด "ลบ" ได้ทั้งโพสต์และความคิดเห็นของทุกคน

## เอกสาร API

ทุก endpoint ตอบเป็น JSON ถ้าผิดพลาดจะได้ `{ "error": "ข้อความ" }` ระบบจำการเข้าสู่ระบบด้วยคุกกี้ `univibe.sid` (httpOnly)

| Method | URL | ข้อมูลที่ส่ง | ผลลัพธ์ |
|---|---|---|---|
| GET | `/api/health` | — | `200 { ok, app, db }` |
| POST | `/api/auth/register` | `studentId, birthDate (YYYY-MM-DD), username, email, password` | `201 { user }` และเข้าสู่ระบบทันที / `400` ข้อมูลไม่ถูกต้องหรือไม่ตรงทะเบียน / `409` ข้อมูลซ้ำ |
| POST | `/api/auth/register-teacher` | `fullName, faculty, department, staffId, username, email, password` | `201` บัญชีสถานะรออนุมัติ / `400` / `409` |
| POST | `/api/auth/login` | `username, password` | `200 { user }` / `401` username หรือรหัสผ่านผิด / `403` ถูกระงับหรืออาจารย์ยังไม่อนุมัติ / `429` พยายามบ่อยเกินไป |
| POST | `/api/auth/logout` | — | `200` |
| GET | `/api/auth/me` | — | `200 { user }` / `401` ยังไม่ได้เข้าสู่ระบบ |
| POST | `/api/auth/reset-password` | `studentId, birthDate, newPassword` | `200` / `400` ข้อมูลไม่ตรงทะเบียน |
| GET | `/api/admin/teachers?status=pending` | — (เฉพาะแอดมิน) | `200 { teachers }` / `401` / `403` |
| POST | `/api/admin/teachers/:id/approve` | — (เฉพาะแอดมิน) | `200 { teacher }` / `404` / `409` ดำเนินการไปแล้ว |
| POST | `/api/admin/teachers/:id/reject` | — (เฉพาะแอดมิน) | `200 { teacher }` / `404` / `409` |

### ช่วงที่ 3: โพสต์ ความคิดเห็น ติดตาม แจ้งเตือน ผู้ใช้

ทุก endpoint ด้านล่างต้องเข้าสู่ระบบก่อน (ไม่เช่นนั้นได้ `401`) การส่งรูปใช้ `multipart/form-data` ฟิลด์ `images` (โพสต์ ≤10 รูป คอมเมนต์ ≤4 รูป) แต่ละรูป JPG/PNG/WebP ไม่เกิน 2 MB

| Method | URL | ข้อมูล | ผลลัพธ์ |
|---|---|---|---|
| GET | `/api/posts/feed?scope=all\|following&before=<id>` | — | `200 { posts, nextCursor }` ครั้งละ 10 โพสต์ |
| POST | `/api/posts` | `text, visibility (public/followers), images` | `201 { post }` / `400` |
| GET | `/api/posts/:id` | — | `200 { post }` / `404` (ไม่มีสิทธิ์ดูก็ตอบ 404) |
| PATCH | `/api/posts/:id` | `text, visibility` | `200` / `403` ไม่ใช่เจ้าของ |
| DELETE | `/api/posts/:id` | — | `200` (เจ้าของหรือแอดมิน) / `403` |
| POST / DELETE | `/api/posts/:id/like` | — | `200 { liked, likesCount }` |
| GET | `/api/posts/:id/comments` | — | `200 { comments }` |
| POST | `/api/posts/:id/comments` | `text, images` | `201 { comment }` |
| PATCH / DELETE | `/api/comments/:id` | `text` | แก้: เจ้าของ / ลบ: เจ้าของ เจ้าของโพสต์ หรือแอดมิน |
| GET | `/api/posts/search?q=` | — | `200 { posts, nextCursor }` |
| GET | `/api/posts/hashtag/:tag` | — | `200 { posts, nextCursor }` |

### เหตุการณ์เรียลไทม์ (Socket.io)

เชื่อมต่อที่ origin เดียวกับเว็บ ใช้ session เดียวกัน (ไม่ได้ล็อกอินหรือคุกกี้ปลอมจะเชื่อมต่อไม่ได้) เซิร์ฟเวอร์อ่านและตรวจลายเซ็นคุกกี้ `univibe.sid` เองในขั้น handshake

| ทิศทาง | เหตุการณ์ | ข้อมูล |
|---|---|---|
| เซิร์ฟเวอร์ → ไคลเอนต์ | `message:new` | `{ conversationId, message }` ข้อความใหม่ในห้องที่เราเป็นสมาชิก |
| เซิร์ฟเวอร์ → ไคลเอนต์ | `message:update` | `{ conversationId, message }` ข้อความถูกแก้ไข/ลบ |
| เซิร์ฟเวอร์ → ไคลเอนต์ | `messages:read` | `{ conversationId, userId }` มีคนอ่านแล้ว |
| เซิร์ฟเวอร์ → ไคลเอนต์ | `typing` | `{ conversationId, userId, displayName, isTyping }` |
| เซิร์ฟเวอร์ → ไคลเอนต์ | `presence` | `{ userId, online }` คู่สนทนาออนไลน์/ออฟไลน์ |
| ไคลเอนต์ → เซิร์ฟเวอร์ | `typing` | `{ conversationId, isTyping }` (เซิร์ฟเวอร์ตรวจสิทธิ์ก่อนส่งต่อ) |

## ความปลอดภัยที่ทำแล้ว

- รหัสผ่านเก็บเป็น hash ด้วย bcrypt และไม่ถูกส่งกลับไปกับข้อมูลผู้ใช้
- session เก็บใน MongoDB คุกกี้เป็น httpOnly + sameSite และสร้าง session ใหม่ทุกครั้งที่เข้าสู่ระบบ
- ตรวจข้อมูลทุกช่องที่ฝั่งเซิร์ฟเวอร์ (หน้าเว็บตรวจเพื่อช่วยผู้ใช้เท่านั้น)
- ข้อความ error ตอนเข้าสู่ระบบและยืนยันทะเบียนเหมือนกันทุกกรณี ไม่บอกว่ามีบัญชีหรือข้อมูลใดอยู่ในระบบ
- ล็อกอินผิดเกิน 10 ครั้งใน 15 นาที (ต่อ IP + username) จะถูกจำกัด
- แอดมินระงับบัญชีแล้วมีผลทันที (ตรวจสถานะผู้ใช้ทุกคำขอ)
- ปฏิเสธคำขอเปลี่ยนข้อมูลที่ส่งมาจากเว็บอื่น (ตรวจ Origin)
- หน้าเว็บแสดงข้อมูลผู้ใช้ด้วย `textContent` เสมอ ป้องกัน XSS
- อัปโหลดรูป: จำกัดชนิด (JPG/PNG/WebP) และขนาด (2 MB) ตรวจ "ลายเซ็น" ของไฟล์จริงกันไฟล์ปลอม ตั้งชื่อไฟล์แบบสุ่ม และเก็บนอกโฟลเดอร์ `public/`
- เปิดดูรูปได้เฉพาะผู้ที่เข้าสู่ระบบ และกัน path traversal ด้วยการจำกัดชื่อไฟล์
- โพสต์ที่ไม่มีสิทธิ์ดู (เฉพาะผู้ติดตาม) ตอบ 404 เหมือนไม่มีโพสต์ ไม่เปิดเผยว่ามีอยู่
- ค้นหาด้วยข้อความที่ผู้ใช้พิมพ์ ผ่านการ escape อักขระพิเศษของ regex
- ยืนยันรหัสผ่านก่อนเปลี่ยนอีเมลหรือลบบัญชี
- Socket.io ใช้ session เดียวกับเว็บ และปฏิเสธการเชื่อมต่อจาก origin อื่น (กัน Cross-Site WebSocket Hijacking)
- ส่งข้อความ/อ่าน/พิมพ์ได้เฉพาะสมาชิกของห้อง ตรวจสิทธิ์ที่เซิร์ฟเวอร์ทุกครั้ง
- ระบบบล็อกตรวจที่เซิร์ฟเวอร์ ทั้งการติดตาม การเริ่มแชท และการส่งข้อความ
- อัปโหลดไฟล์ส่งงาน: จำกัดชนิด (PDF/docx/zip/รูป) และขนาด (10 MB) ตรวจ "ลายเซ็น" ของไฟล์จริงให้ตรงกับชนิดที่ประกาศ ตั้งชื่อไฟล์แบบสุ่ม เก็บนอก `public/` และเปิดผ่านเส้นทางที่ตรวจสิทธิ์ (เจ้าของงาน อาจารย์ผู้ดูแล แอดมินเท่านั้น) พร้อม `nosniff`
- ไฟล์ที่ถูกปฏิเสธหรือส่งไม่สำเร็จจะถูกลบออกจากดิสก์ทันที ไม่ทิ้งไฟล์ค้าง
- สิทธิ์ของวิชาตรวจที่เซิร์ฟเวอร์ทุกเส้นทาง: อ่านประกาศ/งาน/รายชื่อได้เฉพาะสมาชิก สร้างและให้คะแนนได้เฉพาะอาจารย์ผู้ดูแล แอดมินลบประกาศและงานได้แต่สร้างไม่ได้
- เวลาเรียนห้องหรืออาจารย์ชนกันถูกบล็อกเสมอ ส่วนนักศึกษาเรียนชนจะเตือนและให้ยืนยันก่อนบันทึก
- Socket.io อ่าน session จากคุกกี้โดยตรงและตรวจลายเซ็น แทนการเสียบ express-session ใน engine.io (ที่เคยทำให้เซิร์ฟเวอร์ล้มเมื่อ handshake ถูกตัดกลางคัน) และมีตัวดัก `unhandledRejection` กันงานเบื้องหลังล้มทั้งระบบ
- รายงานโพสต์ได้เฉพาะโพสต์ที่ตัวเองมองเห็น (โพสต์ที่ไม่มีสิทธิ์ดูตอบ 404) ห้ามรายงานโพสต์ตัวเอง และรายงานซ้ำไม่ได้ (unique index) แอดมินจึงไม่ถูกท่วมด้วยรายงานซ้ำจากคนเดิม
- แอดมินระงับบัญชีแล้วผู้ใช้ถูกเตะออกทุกช่องทางทันที: เว็บ (ตรวจสถานะทุกคำขอ) เข้าสู่ระบบใหม่ไม่ได้ และตัดการเชื่อมต่อ Socket.io ที่เปิดอยู่ ระงับตัวเองหรือแอดมินด้วยกันไม่ได้
- รายการผู้ใช้ของแอดมินไม่ส่ง `passwordHash` และค้นหาด้วยการ escape อักขระพิเศษของ regex
